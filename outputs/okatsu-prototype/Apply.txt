Nioh 1 — Okatsu sword prototype

Enter Okatsu's mission with a sword equipped and her actor loaded.
Run Start-Okatsu.ps1. It reuses the saved controller mapping, prepares current
addresses, builds the session DLL if needed, and enables continuous play.
Read play-status.json for enabled/waiting/error status.

LB + Circle: tap and release Circle for Okatsu's Charged Rush (C64/1220).
Hold both for 0.25 seconds for Okatsu's Leaping Slash (C66/1230).
Directional movement, lock-on and stance retention were playtested.
Release Circle between uses; LB can remain held. No one-use limit or timer.
Tap fires on release so a hold cannot also fire the tap attack.

Run Stop-Okatsu.ps1 to disable. The loader waits for native move recovery.
Clean actor/session changes trigger automatic reacquisition, without calibration.
If Okatsu's resources are absent, the launcher waits instead of using old pointers.

Requires the researched Nioh 1 build (SHA256 in findings.json), saved DS4 mapping,
64-bit Python, and GCC/G++ on PATH. MinHook is included in third_party/minhook.
Python selection: -PythonRuntime, NIOH_PYTHON, installed Python, then bundled fallback.
Start-Okatsu.ps1 accepts -MinHook for another MinHook source directory.
For another Steam library, set NIOH_EXE to the full nioh.exe path before launching;
the exact executable hash and process identity checks still apply.
No game files are modified. Inactive DLLs remain allocated until game exit.
Both moves and imported voice removal were confirmed by the user; combat FX remain.
Implemented, awaiting playtest: 2x Charged Rush startup through frame 30,
and native Ki Pulse windows for both moves with native pulse input transitions.
Player damage ownership still needs verification.
